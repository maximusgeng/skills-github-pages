Привет! Это мой первый пост в блоге на GitHub Pages.

## О чём этот пост

В рамках лабораторной работы по дисциплине **АРПО** я настроил
непрерывную интеграцию (CI) для проекта 2D-платформера на Unity.

## Что такое GitHub Actions

**GitHub Actions** — это платформа для автоматизации процессов разработки.
Сценарий описывается декларативно в YAML-файле, который хранится прямо
в репозитории:

```yaml
name: Unity 2D Platformer CI/CD
on:
  push:
    branches: [ "main" ]
jobs:
  sanity_check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
```

## Основные компоненты

| Компонент | Назначение |
|---|---|
| Workflow | Сценарий верхнего уровня |
| Trigger | Событие, запускающее пайплайн |
| Job | Изолированный набор шагов |
| Step | Один шаг задачи |
| Runner | Виртуальная машина для выполнения |
| Action | Готовый переиспользуемый плагин |

## Зачем нужен Sanity Check

Проверка *sanity check* выполняется до основных задач и быстро отвечает на
вопрос: «а проект ли это вообще?». Если структура нарушена — пайплайн
останавливается, и дорогостоящие шаги не запускаются.

Именно такая проверка и зеркалирование репозитория в резервный контур
и были реализованы в моей работе.
